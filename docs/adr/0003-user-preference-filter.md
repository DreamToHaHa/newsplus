# ADR-0003: 用户决策过滤机制

抓取始终全量进行并入库；**用户决策（Preference）只决定哪些条目进入推送**。被过滤的条目不推送，但数据保留，方便日后放开限制。

**Context**：用户希望"对不感兴趣的内容可以不推送"，但又不愿因过滤而丢失数据——抓取到的信息要一直留存，过滤仅是推送层的视图。用户决策的表达方式有对话式（微信里对 OpenClaw 说"不推 XX"）和配置文件两种。

**Decision**：选择**对话式**为主——用户直接在微信中告诉 OpenClaw 偏好，OpenClaw 靠其记忆/standing orders 机制记住并应用到后续汇总。过滤粒度支持主题/关键词黑名单与按源开关两层。命中过滤的条目整条不推送（标题也不占位），但仍保留在抓取数据中。

**Consequences**：过滤逻辑依赖 OpenClaw 的对话记忆正确落地，存在"记错/遗忘"的风险点；实施时需验证 OpenClaw 的 standing orders / memory 机制并给规则留出可审计路径。数据全量留存，日后再做公众号/短视频改造时不缺素材。

**Status**: accepted
